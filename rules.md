# Жёсткие правила проекта

**Формат:** `ПРАВИЛО — причина (дата добавления)`.
Правила не дублируются и не противоречат друг другу. Противоречие — повод для консолидации.

## Базовые правила
1. **НИКОГДА** не генерируй код, если для него нет задачи в `development-plan.xml`.
2. **ВСЕГДА** начинай с `MODULE_CONTRACT`. Нет контракта — нет кода.
3. **ПЕРЕД** изменением модуля проверь его зависимости в `knowledge-graph.xml` — включая тех, кто зависит от НЕГО (`provides_to`).
4. **ОБЯЗАТЕЛЬНА** семантическая разметка для блоков длиннее 50 строк.
5. **НЕ ИСПОЛЬЗУЙ** магические числа — конфигурируемые параметры только в конфиг-файле.
6. **ЕСЛИ** реализация уходит от контракта — остановись и запроси уточнение, не импровизируй.
7. **НИКОГДА** не коммить с падающими тестами или невалидным XML.
8. **НЕ КОММИТЬ** секреты — все ключи API только через `.env` (gitignored). — ключи в коде утекают в репозиторий (2026-08-02)
